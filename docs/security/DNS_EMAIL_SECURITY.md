## 1. Objectives & Threat Model

ExzaEstate generates customer-critical financial communications including booking confirmations, money receipts (`REC-YYYY-XXXX`), customer running account statements, and installment payment reminders. Spoofed emails impersonating ExzaEstate pose severe financial fraud risks to property buyers.

To completely prevent email spoofing, phishing, and domain hijacking, strict cryptographic and DNS policy enforcement is mandated across all corporate and transactional domains.

---

## 2. DNS Authentication Records Specification

### 1. Sender Policy Framework (SPF)

Restricts which mail transfer agents (MTAs) are authorized to send email on behalf of `exzaestate.com`:

```dns
exzaestate.com.  IN  TXT  "v=spf1 include:_spf.exzaestate.com include:sendgrid.net -all"
```

- `-all` enforces **hard fail**: Any server not explicitly authorized must be rejected by the receiving mail server.

---

### 2. DomainKeys Identified Mail (DKIM)

Provides cryptographic signature verification for email authenticity and tamper-proofing:

```dns
s1._domainkey.exzaestate.com.  IN  TXT  ( "v=DKIM1; k=rsa; p=MIIBIjANBgkqhkiG9w0BAQEFAAOCAQ8AMIIBCgKCAQEA1vF...[2048-bit RSA Public Key]...IDAQAB" )
```

- Minimum key length: **2048-bit RSA**.
- Canonicalization: `relaxed/relaxed` for both header and body.
- Selector rotation: Conducted bi-annually (`s1` and `s2` selectors).

---

### 3. Domain-based Message Authentication, Reporting & Conformance (DMARC)

Enforces strict policy handling for messages that fail SPF or DKIM alignment:

```dns
_dmarc.exzaestate.com.  IN  TXT  "v=DMARC1; p=reject; sp=reject; pct=100; adkim=s; aspf=s; rua=mailto:dmarc-reports@exzaestate.com; ruf=mailto:dmarc-forensics@exzaestate.com; ri=86400"
```

#### Policy Directive Breakdown:

| Tag         | Value        | Security Impact                                                                         |
| :---------- | :----------- | :-------------------------------------------------------------------------------------- |
| `p=reject`  | **reject**   | Receiving mail servers must immediately drop/reject any message failing authentication. |
| `sp=reject` | **reject**   | Applies the same strict reject policy to all subdomains.                                |
| `pct=100`   | **100%**     | Applies policy to 100% of all outbound mail (zero permissive sampling).                 |
| `adkim=s`   | **strict**   | Enforces strict DKIM alignment (sending domain must match d= tag exactly).              |
| `aspf=s`    | **strict**   | Enforces strict SPF alignment (envelope sender must match from domain exactly).         |
| `rua`       | `mailto:...` | Sends daily aggregate XML authentication reports for monitoring.                        |
| `ruf`       | `mailto:...` | Sends real-time failure forensic reports on suspicious messages.                        |

---

### 4. Mail Transfer Agent Strict Transport Security (MTA-STS)

Prevents man-in-the-middle (MITM) downgrade attacks on inbound SMTP connections:

```dns
_mta-sts.exzaestate.com.  IN  TXT  "v=STSv1; id=2026100801"
```

Policy file served at `https://mta-sts.exzaestate.com/.well-known/mta-sts.txt`:

```text
version: STSv1
mode: enforce
mx: mail.exzaestate.com
max_age: 604800
```

---

## 3. Verification & Monitoring Protocol

1. **Daily DMARC Report Ingestion:** Aggregate DMARC reports are processed to detect unauthorized senders attempting to impersonate the brand.
2. **Mailpit Development Mode:** In local and staging environments, Mailpit is used to verify that headers and DKIM signatures pass without sending external emails (`docker-compose.yml`).
3. **Outbound Notification Health Check:** Transactional emails generated by `apps/backend/src/modules/notification/email/email.service.ts` include verified headers and fail closed if DKIM signing fails.
